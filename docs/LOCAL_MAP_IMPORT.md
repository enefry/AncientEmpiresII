# 自由对战和本地地图

从主菜单进入 PLAY → SKIRMISH。可选 12 张原版地图及 8 张历史追加地图，共 20 张，或点“导入本地地图”从系统“文件”选择地图。追加地图的来源与转换说明见 [OFFICIAL_BONUS_MAPS.md](OFFICIAL_BONUS_MAPS.md)。在线地图服务不接入。

选择地图后可预览地形，为每个阵营选择真人、CPU 或关闭，并独立设置队伍。至少开启两个阵营、分属两支队伍。支持本机真人轮流、真人与 CPU 混合，以及纯 CPU 观战。起始金币使用原版 500～200000 的选项，单位上限使用原版 10～200 的选项；自由对战可招募全部常规兵种。开始对战和回合交接时自动定位当前阵营的指挥官或城堡。

同队单位可穿行但不能重叠落点、互相攻击或夺取同队建筑；同队建筑可治疗。关闭阵营的单位移除、建筑中立化。阵营失去全部存活指挥官和城堡后跳过其回合；仅剩一支队伍时显示获胜队伍。

## 导入格式

- 原版 `.aem`：保留原始大端二进制格式、按列存储的地形和像素坐标偏移；坐标按原版除以 24 转为格坐标。
- `.json`：可使用工程导出的自由对战 JSON，或参考 [示例地图](../Examples/skirmish-map.json)。最少包含 `width`、`height`、`rows` 和 `units`；`name` 可选，省略时取文件名。若提供 `kind`，必须为 `skirmish`。

`rows[y][x]` 以行为顺序存储地形，地形 ID 为 0～46。单位最少包含 `type`（0～11）、`fraction`（1～4）、`x`、`y`。每个参与阵营必须有自己的城堡：蓝军 40、红军 42、绿军 44、黑军 46。阵营回合顺序沿用原版按列扫描城堡的顺序，不一定从蓝军开始。中立村庄和城堡分别为 37、38。

导入限制为 1 MB、宽高各 2～64 格、最多 800 个单位、2～4 个有城堡的阵营。单位必须在地图内、归属地图中存在的阵营且不能重叠；截断、非法地形、非法坐标和额外二进制尾部数据均拒绝导入。

导入时复制内容到本机，不依赖原文件继续存在。失败时显示原因，不改变已有地图或正在配置的对战。导入地图可在配置页删除，需要确认；每份对局存档包含地图和配置，因此删除导入地图不影响已有自动或手动存档。旧战役存档保持兼容，自由对战不会解锁战役关卡。

## 验证

引擎测试记录见 `.noindex/logs/skirmish-package.log`；最终自由对战 UIKit 与端到端验证见 `.noindex/logs/skirmish-final-ui.log`，6 个 UIKit 用例和 1 个完整 UI 用例全部通过。受影响的战役、AI、经济、建筑、状态与存档回归共 64 个用例通过，记录在 `.noindex/logs/skirmish-final-validation.log`（该次运行的镜头可点击 UI 断言随后修复，并由最终 UI 日志确认通过）。覆盖全部内置地图的对局及存档、原版二进制导入、JSON 输入校验、队伍规则、关闭阵营、经济、四方真人交接、纯 CPU 回合边界、本地持久化、地图删除后的手动存档恢复和菜单重启续玩。
