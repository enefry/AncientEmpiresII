## 平台与目标

- 用户已确定：优先只在 iOS 上运行；macOS 使用 iOS on Mac。
- 用户已确认整个应用使用纯 UIKit，不使用 SwiftUI 或 SpriteKit。页面、地图、单位和战斗表现都由 UIKit 视图及其 Core Animation / Core Graphics 绘制；游戏规则使用平台无关的 Swift。
- 同一 iOS 应用适配 iPhone、iPad，以及 Apple Silicon Mac 上的 iOS on Mac。无需独立 macOS target 或 Mac Catalyst target。
- 暂定最低 iOS 17；这是方案默认值，尚未确认目标设备需求。
- 保留原版像素画风、地图和回合制玩法，现代化触摸操作、屏幕适配和存档。第一阶段以离线单机为目标。

## 实现边界

### 数据还原

保留输入 JAR 原文件；通过可重复运行的工具读取和转换资源，不手工修改原包。

1. 提取图片，解析精灵帧、锚点、动画序列和原版时序。
2. 解析单位和地形配置，建立带来源路径的类型化数据。
3. 结合 Java 读取逻辑确认地图格式、坐标顺序、阵营、初始单位和附加字段；不能仅根据前几个字节猜完整格式。
4. 分析 Java 字节码或反编译结果，恢复伤害、反击、占领、收入、恢复、升级、特殊能力和胜负判断。
5. 追踪剧情状态机和语言表，确认脚本备份是否与运行逻辑一致。
6. MIDI 保留为原始材料；先验证 Apple 平台播放效果，必要时离线渲染成可循环的音频，再核对旋律与循环点。

无法确认的规则登记为待验证项；任何用于原型的替代规则必须明确标注，不能当作已还原的原版行为。

### 游戏规则与表现

- `GameCore`：基于 struct / enum 的地图、单位、阵营、回合和剧情状态，不依赖 UIKit 或图形框架。
- 用户输入转换为命令；规则层校验合法性，原子更新状态，并产生移动、伤害、死亡等事件。
- `GamePresentation`：根据事件更新 UIKit 视图、图层和像素画布。动画不负责决定伤害或推进回合。
- `GameContent`：转换后的地图、单位、地形、剧情、纹理及音频。
- `SaveStore`：版本化快照、原子写入与失败处理。游戏状态和随机数状态可恢复，渲染节点不进入存档。
- AI 通过与玩家相同的合法命令操作。是否需要后台计算由实际性能决定；先避免无必要的并发复杂度。

上述名称是模块职责建议，不要求一开始拆成多个独立包或建立复杂协议层。

### 显示与操作

- 原始图块为 24×24 像素；采用 nearest filtering、对齐像素的坐标和可选整数倍缩放，避免插值导致模糊。
- 地图视口与操作区分开布局，不把整套 240×320 旧界面直接拉伸到现代屏幕。
- 点击单位显示移动和攻击范围，点击目标发起行动；明确提供取消、待机与结束回合入口。
- 大地图支持拖动浏览；缩放与点击手势需要仲裁，避免拖动结束误下指令。
- 手机优先竖屏布局；iPad 和 Mac 窗口使用自适应视口，具体横屏支持在第一阶段验证。
- iOS on Mac 提供鼠标点击、地图拖动，以及方向键、确认和取消操作。界面不依赖触摸、振动或固定全屏尺寸。
- 单位状态和可执行操作在现代 UI 中提供文字信息，避免完全依赖像素图和颜色区分。

### 生命周期与存档

- 使用显式状态表示选择单位、选择移动目标、选择攻击目标、动画、AI 回合和剧情，阻止动画期间重复提交行动。
- 在稳定的规则状态边界保存；进入后台时暂停表现并尝试保存最近的完整状态，不能只依赖退出回调保存。
- 动画中断后按已提交的规则状态重建画面，不能重复扣血、发收入或触发剧情。
- 存档包含版本、内容版本、关卡、单位、阵营经济、当前回合、剧情进度和随机数状态；旧版本不兼容时明确提示。
- 写入失败保留上一次有效存档并提示用户；损坏存档不导致启动崩溃。
- 第一阶段只允许一个活跃对局会话，避免多个窗口或场景同时写入同一存档。

## 实施阶段

### 0. 先保存原版代码参考

根据用户后续确定的顺序，先从 JAR 恢复可检索的 Java 参考资料，再开展 Swift 移植。保留原 class / 资源、原名反编译代码、自动消除命名冲突的阅读版、独立工具交叉参考和字节码清单；人工命名与规则解释另写文档，不覆盖生成文件。

本阶段已经生成全部 18 个类的三套反编译参考视图，并追加按职责命名的 `java-named/` 视图；保存代码职责索引、类命名映射、成员映射和初步规则笔记，入口见 [reference/README.md](../reference/README.md)。部分控制流和类型推断仍有反编译歧义，未恢复为可编译、可运行的 Java 工程；这些缺口需要在使用相应规则前核对。

### 1. 可验证的资源和规则基线

产出资源清单、转换工具、地图格式说明，以及规则证据表。优先确认第一关所需内容，必要时通过 J2ME 运行环境观察原版进行对照。

验收：第一关地图、初始兵种、位置、阵营和地形能与原包读取结果对应；无越界索引；未知字段和未验证规则有明确记录。

### 2. 第一关完整可玩

建立 iOS 工程，完成地图渲染、单位选择、移动、攻击、反击、待机、回合切换、AI、该关胜负条件和自动存档。接入该关必需的剧情触发；第一关之外的兵种不作为本阶段完成条件。

验收：能从进入关卡玩到胜利或失败；AI 能结束回合且不会死循环；关键规则有原版依据；后台恢复和读档不会重复执行行动。

### 3. 全部内容与表现还原

扩展其余地图、兵种特殊能力、完整战役剧情、招募和经济系统、战斗演出、音乐与自由对战。根据原版证据调整 AI 和细节。

验收：每关入口、剧情触发和通关路线经过检查；同一版本同一存档能稳定恢复；已验证部分与临时替代部分分别报告。

### 4. iOS 与 iOS on Mac 体验验证

检查不同手机尺寸、iPad、大地图视口、Mac 窗口缩放、鼠标键盘、音频中断和性能，再准备分发。

## 验证与构建规则

- 规则测试优先使用 Swift Testing：地形移动消耗、阻挡、射程、伤害边界、反击条件、回合经济、剧情触发和存档恢复。测试使用经确认的例子，不只复述实现。
- 自动化规则测试、Simulator 构建/交互、iPhone/iPad 真机和 iOS on Mac 实测分别记录；构建通过不能代替玩法或兼容性验证。
- 对未知规则保留来源、推断和对照结果；若不能运行原版，就明确保留相应的行为一致性验证缺口。
- 构建缓存使用工程根目录 `.noindex/DerivedData`；多 worktree 时使用有限、稳定的 worktree 专用子目录。
- 转换中间文件、构建日志和验证产物分别放入 `.noindex/tmp`、`.noindex/logs`、`.noindex/artifacts`，重复任务复用，不建立随机临时工程。
- 需要签名或设备访问的检查按实际环境权限执行，不把沙箱权限失败归因于源代码。
