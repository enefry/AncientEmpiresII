# 游戏设定与数值表

本页区分语言表的故事/描述和代码规则；数字取自选定 JAR 的配置。英文名保留，中文名只是本次资料说明用名，不代表原版官方译名。

## 背景与玩法

故事发生在 Thorin 王国。Galamar 与 Valadorn 两兄弟抵御入侵、追寻被夺走的水晶，最后与 Saeth 在 Ancient Citadel 对决。水晶既能保护王国，也能引出毁灭力量 Heaven's Fury。人物、预言和对话原文在 [文本 215–287](TEXTS.md)；不是根据记忆重写的剧情。

这是方格地图上的回合制战棋：单位移动、攻击、占领城镇/城堡、招募、修复、召唤骷髅，阵营依次行动。地图无距离伤害衰减，也未在射程逻辑发现视线/树林遮挡判断。默认 HP 100。棋盘图块 24×24 像素。

选定 v2.5 带自由对战、队伍配置、地图编辑、地图导入导出及开发控制台；这些是该扩展版本的范围，不应混同于最早发行版。原包 Manifest 开启 `Developer-Mode`、设定 `Override-FPS: 15`、`Disable-Intro: true`。

## 模式与阵营

战役地图 `m0…m7`，自由对战 `s0…s11`。战役固定蓝方真人、红方 CPU，队伍分别为 0、1。自由对战可配置 CPU（mode 0）、真人（1）、关闭（2）；颜色 ID 1 蓝、2 红、3 绿、4 黑，队伍 ID 独立于颜色。判断敌友用队伍，不仅用颜色。

自由对战轮转队列按 x 外层 / y 内层扫描地图时首次发现的有色城堡建立，不一定是蓝红绿黑顺序。关闭阵营的建筑中立化，单位不创建。每个阵营最多登记 4 个指挥官。

自由对战起始金币可选 `500, 1000, 2000, 5000, 10000, 25000, 50000, 75000, 100000, 150000, 200000`；单位上限 10…200，每次增加 10。战役单位上限初始化为 100。依据：`MainDisplayable.java:35, 3177, 3295`；指挥官数量：`Unit.createUnitEx:124`。

指挥官外观/名称：Galamar、Demon Lord、Valadorn、Saeth；变体 ID 分别 0…3，不能用兵种文件 `king` 推断为普通国王。水晶不能发动常规攻击，其攻击区间没有宽度，不能直接调用随机伤害函数。

全量配置及 `CharPos` 见 [units.json](data/units.json)。`CharPos` 是侧面战斗画面里小人的布局，不是地图格坐标。地图一支单位代表多人，HP 影响实际画出的战斗人数；人数本身不再次乘入伤害公式。

每级增加攻击上下界和防御各 2；移动预算、射程、价格不随晋级增加。非指挥官显示名按 `min(rank/2,3)` 分四档，所有英文等级名保留在文本 139…183。

Tile ID 与 Type ID 不能混用。图块 27 是废墟，34 是神庙，37/38 是中立城镇/城堡；39/40 蓝、41/42 红、43/44 绿、45/46 黑；47 熔岩。完整映射包含 0…14 水面变体和其它道路/建筑变体，见 [terrain.json](data/terrain.json) 和 [图块图鉴](previews/tiles.png)。

神庙 34：攻击额外 +25、防御额外 +15；其 Type 7 还提供 +15 地形防御，所以该格总防御加成是 +30。这些不是所有“建筑”共用的奖励。

回合开始，己方城镇每座 +30 金币、城堡每座 +50；只按所属阵营发钱，同队盟友的建筑不替你产生收入。己方活单位在 Type 7 公共建筑，或同队拥有的城镇/城堡上恢复最多 20 HP，封顶 100。中立城镇/城堡不满足同队治疗条件；废墟保有地形防御但无所属方、无收入。

占领必须执行菜单行动，不是落格自动归属；同队建筑不可抢占。修复将废墟换成中立城镇 37，消耗行动；随后才可再占领，没有直接扣金币的逻辑。投石车可攻击射程内没有活单位占据的非同队城镇，一次行动将其改成废墟 27；不是按建筑 HP 扣血，不能因此摧毁城堡。

招募地点是自己的城堡（菜单检查所有权），需金币足够、解锁兵种、扣除骷髅后的活单位数低于上限，并能从城堡找到一个可到达空格。购买创建满血单位；复活保留指挥官原对象、等级与经验并恢复 HP。战斗死亡后指挥官离开棋盘，每次死亡价格 +200，涨到 1000 后不再增加；第一次复活通常为 400。依据：`MainDisplayable:2995,3721,4282,6703`。

## 可执行行动

普通单位可先移动再攻击/占领/修复/召唤/待机，投石车有移动或攻击的限制。移动过程未立即耗尽单位行动，`finishMove` 这个名字实际承担“结束行动”的职责：将状态改为 2、清理落格墓碑、发放幽灵光环。取消移动的交互路径保留原坐标并回到选择状态；实际选择/取消顺序还需要原版运行对照。

完整规则计算与副作用顺序见 [核心算法](ALGORITHMS.md)。
