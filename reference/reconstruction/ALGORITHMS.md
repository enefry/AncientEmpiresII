# 核心算法还原

公式用语义名表达，不改原 Java。除特别注明，数值运算是 Java int 整数算术，除法向零截断，byte/short 的强制转换保留有符号溢出语义。多数证据来自 `reference/inputs/AEIIRM_src/src/aeii`；字节码位置都指向选定 JAR 的 `reference/bytecode`。

## 随机数与伤害

随机区间函数：`lower + abs(java.util.Random.nextInt()) % (upper-lower)`。一般情况上界排除，取模有分布偏差；`Integer.MIN_VALUE` 取绝对值仍为负数，可能落到区间外。上下界相等会除零，因此水晶不能进入普通攻击运算。证据：`Renderer.java:120`；原符号 `aeii.c.a(II)I`，[字节码](../bytecode/aeii/c.javap.txt) 225 行。

定义：

```text
攻击加成 = 状态攻击加成
         + (弓箭手等 anti_air 对 flying 目标 ? 15 : 0)
         + (幽灵对骷髅 ? 15 : 0)
         + (两栖单位位于水域 ? 10 : 0)
         + (攻击者位于图块 34 ? 25 : 0)

防守加成 = 状态防御加成 + 目标所在 Type 的地形防御
         + (目标两栖且位于水域 ? 15 : 0)
         + (目标位于图块 34 ? 15 : 0)

A = random(攻击下界, 攻击上界) + 攻击加成
D = 目标基础防御 + 防守加成
damage = clamp((A-D) * 攻击者当前HP / 100, 0, 目标当前HP)
目标HP -= damage
攻击者经验 += (目标攻击下界 + 目标攻击上界 + 目标基础防御) * damage
```

`Unit.attackUnit:233` 与原符号 `aeii.a.c(Laeii/a;)I`；[伤害字节码](../bytecode/aeii/a.javap.txt) 569 行。等级增加后的目标属性计入经验权重；临时状态/地形不计入该经验权重。

例：rank 0 士兵在道路上攻击满血道路士兵，随机值 50…54、目标防御 5，造成 45…49。若本次取 50，则目标剩 55 HP；该目标反击若也取 50，造成 `(50−5)*55/100=24`，先攻者剩 76。双方均只掷一次攻击随机数，不是每个战斗小人掷一次。

## 反击与结算

反击条件：目标不是状态 4、HP>0、与攻击者曼哈顿距离=1、目标兵种最小射程=1。弓箭手可贴身反击；投石车最小射程=2，不能反击。已经结束自己行动的单位仍可反击，条件未排除状态 2。

侧面动画开启时：建立两侧动画对象保存受伤前状态 → 先攻扣血 → 符合条件的存活目标按受伤后 HP 反击 → 保存双方最终 HP/人数 → 播放动画 → `finishAttack` 处理升级/中毒/死亡/行动结束。依据：`MainDisplayable.createCombatAnimation:9768`。

关闭侧面动画或目标没有战斗角色（水晶）时：`gameState=13`，先攻、等待逻辑计时 800、反击、再次等待后结算；也是先攻后反击，但数值修改发生在地图动画阶段。不能将“两种模式都开场一次性结算”作为原版时序。依据：`MainDisplayable:1217,4160`。

`finishAttack:1256` 只给每个存活参战单位调用一次 `promote`；主动攻击者有中毒属性且目标存活时给目标中毒，**并非任何凶狼反击都会施毒**。这个判断没有再次要求主动攻击者存活，因此不要自行加入“攻击者死亡就不施毒”的条件。随后主动攻击者 `finishMove` 耗尽行动。建筑伪目标另走摧毁流程，不调用伤害/反击。

反击资格原符号 `aeii.a.a(II)Z`，[字节码](../bytecode/aeii/a.javap.txt) 682 行。状态 4 在建筑攻击流程中是临时伪单位，不能当普通单位存档。

## 经验与晋级

```text
quality = 当前攻击下界 + 当前攻击上界 + 当前基础防御
threshold = quality * 100 * 2 / 3
若经验 >= threshold：经验减去一次 threshold，rank 加一
新攻击下/上界 = 配置下/上界 + rank*2
新基础防御 = 配置防御 + rank*2
移动预算 = 配置移动预算
```

升级不回复 HP，攻击结算只晋升一级，不是 while 连升。选定 JAR 的晋级方法没有 `rank<9` 上限判断；源码注释残留的限制不生效。`setRank` 参数为 byte，rank 128 会绕回 −128；这是原版极端边界，不应把“没有显式等级上限”说成无限无溢出成长。

依据：`Unit:87,255,260,265`；原符号 `aeii.a.a(B)V` 字节码 206 行（bonus 使用 int，`ishl` 后不截断 byte），`aeii.a.a()Z` 654 行（单次晋级及 `i2b`）。Fernflower 有局部变量合并误差，应以这些指令为准。

## 移动范围：剩余预算传播

棋盘只使用上下左右四邻接，费用计入进入格，起始格本身不扣费。不是 A*；它反复递归更新每格可保留的最大剩余预算：

```text
alpha 初始全 0
visit(x,y,budget,禁止立刻回头的方向):
  若 budget <= alpha[x][y]，返回 false
  alpha[x][y] = budget
  若 expand 且此格无活单位，返回 true
  依次尝试 上、下、左、右：
    nextBudget = budget - enterCost(next)
    若不是禁止方向且 nextBudget >= 0，递归 visit(next)
    expand=true 时找到空格立即成功返回
```

`expand=false` 用于覆盖可达范围；`expand=true` 用于招聘前确认能离开城堡到空格。严格 `budget>alpha` 意味着费用正好耗完、剩余 0 的格不能被标记，也不会成为合法目的格。全道路、移动预算 5 时常规范围最大曼哈顿距离是 4。不要用现代路径库默认的“总消耗 <=5”替换。

进入费用：越界 10000；格上敌队活单位 1000；水晶入山地 1000；飞行 1；两栖入水域 1；其它按地形表。同队单位可穿过；玩家最终落格不可覆盖其它活单位，AI 会调度未行动己方单位腾位置。飞行也不能穿过敌方单位。进行移动的单位在占用查询中提前按目的格登记，见 `getUnit`。

依据：`Unit.fillMoveRangeDataEx:637`、`getRequiredSteps:701`；原符号 `aeii.a.a([[BIIIIBBZ)Z`，[字节码](../bytecode/aeii/a.javap.txt) 1639 行开头 `if_icmple` 已核对；JAR 阅读版 `Unit.method_52` 也吻合。

## 路线重建与剧情直线路线

常规路线从目的格往回递归，比较周围四格 alpha 的最大值；平手按 **上、下、左、右**，到起点再依次追加沿途坐标。不是另一次搜索，也不能任意改变平手顺序，否则动画走法会不同。只应用于已标记可达范围；不可达格直接调用可能出现错误递归。

剧情 `plotRoute(..., false)` 不用地形费用，先横向移动到目标 x，再纵向移动到目标 y，允许地图外坐标。`plotRouteEx` 的另一参数可在目标被占时寻找附近空格；源代码条件带运算符优先级细节，应保留原式作为证据，不能先概括成一般寻路。跟随单位通过 `followerUnit` 排队走入前驱经过的位置。

依据：`Unit.plotRouteEx:500`、`findRouteFromPointToPoint:571`、移动更新 `Unit:745`。

## 射程与目标

`minRange <= abs(dx)+abs(dy) <= maxRange`，限制在地图内；未做路径距离或视线检查。普通单位的总威胁范围是所有可达格的攻击范围并集；投石车只从原格展开攻击范围。范围网格用 127 标记攻击格，正预算表示移动格；两种值不能混为同一含义。

敌人查询按 x 再 y 扫描，同队判定使用 team。墓碑目标模式接受任意阵营墓碑；盟友模式接受同队活单位。投石车若在目标格没有活单位，可构造城镇伪目标（type −1、state 4），中立城镇同样可成为目标。依据：`Unit:350,394,423`。

`getUnit(x,y,0)` 返回首个非墓碑单位；查询 state 1 移动中单位时使用预定目的坐标。`getUnit(...,1)` 返回墓碑。因此召唤的“存在墓碑”与“目的格是否另有活单位”是两个问题，原版不能直接替换为严格的一格一个对象模型。依据：`MainDisplayable.getUnit:6310`。

## 单位状态、墓碑与特殊能力

| 状态 | 含义 |
| --- | --- |
| 0 | 可行动 |
| 1 | 移动动画中（占用查询使用目的格） |
| 2 | 本次行动已结束，地图呈灰色 |
| 3 | 死亡 / 墓碑或离场指挥官 |
| 4 | 建筑攻击用伪目标 |

普通单位战斗死亡后进入 state 3，墓碑计数设 3，每次轮换玩家减 1，<=0 删除。骷髅与水晶死亡直接从单位集合移除。指挥官移到 `(−10,−10)` 保留对象、清状态，供城堡复活；不作为可召唤墓碑。最终关 Saeth 的死亡走剧情标志，不走普通指挥官复活流程。

`finishMove` 会移除落格墓碑，故移动经过墓碑与在墓碑格结束行动不同。召唤消耗女术士的行动，约 400 逻辑计时后删墓碑、同格生成满血己方骷髅并立即结束新骷髅行动，不能让它本回合立即再攻。依据：`Unit.finishMove:851`、`MainDisplayable:4282,4363,5008`。

中毒：状态位 1，攻击和防御各 −10，没有持续扣血，也没有减移动力。施毒时记录的是**当前行动玩家**；当轮转再次到该玩家时去掉毒，不是简单“被中毒方开始回合就清除”。多方自由对战持续时间要按队列推算。

光环：状态位 2，攻击 +10；幽灵完成行动时给曼哈顿 1…2 格内同队活单位设置，重复幽灵不叠加。到了受益单位所属玩家的回合开始去掉光环。这是行动触发状态，不是每帧随位置重新计算的永久范围效果。

依据：`Unit.addEffect/updateEffects:288,305`、`MainDisplayable.sub_cff:6365`；状态核心字节码 `aeii.a.b()V` 753 行已核对。二者可共存，相加后的攻击修正可能互相抵消。

### 战斗收尾与演出细节（2026-10-02 对照补充）

- `MainDisplayable.finishAttack:1255` 在先攻和反击全部结算后才升级；一次只升一级，死亡者不升级。施毒只检查发起攻击者的 bit 7，因此防守狼反击不施毒，发起狼被反击杀死仍会对存活目标施毒。
- 攻击者总会调用 `finishMove`；被反击杀死的幽灵仍给周围友军施加光环。光环逐格查询首个活单位，不能把同格重叠的所有单位都加成。
- 死亡先产生 spark，等待 300 逻辑 ms（6 tick）且镜头到位，再产生向上每 tick 3px 的 smoke，随后切换墓碑或移出地图。烟雾每两 tick 换帧。
- `sub_726:5163` 从墓碑四角 `(±8,±8)` 创建四个 spark，每 tick 沿 `(∓1,∓1)` 移动，6 帧重复三遍。召唤在 8 tick 后完成，火花的 18 tick 生命周期仍会继续，不能随行动刷新清空。
- 召唤不扣金币、不检查购买兵力上限；墓碑所在格已经存在活单位也不阻止召唤。新骷髅的 `finishMove` 会覆盖 `lastFinishedMoveUnit` 为骷髅，并继续删除该格首个残余墓碑。
- 中毒图标采用 `status` frame 0、800 逻辑 ms（16 tick）、初速度 −4 的反弹，起点位于单位上方。光环只产生 spark；属性页/战斗头攻击列显示光环及毒，防御列只显示毒。原资料说明在单位描述前加入文本 98、100、99。

Swift 当前将玩法结果一次提交，队列保存演出前快照，恢复时重放显示而不重复扣血/施法。双阵营轮转与 m7 Saeth 天怒例外已经接入，m0–m7 剧情引用已有自动化覆盖；多玩家同队、原 Java 同种子完整轨迹及逐帧演出仍未验证。旧存档没有墓碑年龄字段时不猜测其剩余寿命。

## 回合、收入与恢复

`currentTurn` 每次切换玩家 +1，不是每完整一轮 +1；关闭玩家递归跳过时也再增加。双人战役 `currentTurn>=2` 意味着红方回合已经过去，重新到蓝方。

轮转顺序：保存当前光标 → 增加 currentTurn、推进队列 → 跳过关闭玩家 → 所有活单位 state 重置 0 → 减少墓碑剩余转换数、移除到期毒/当前方光环、清 AI 支援记账 → 发当前方建筑收入 → 初始化当前方 AI/速度 → 没有活单位也没有城堡的玩家再次跳过。收入提示结束后才进行当前方建筑恢复，最多 +20 HP，再回常规游戏状态。

这里只能操作 currentTurningPlayer 的单位，虽然所有活单位 state 都被重置。不能把每次全局 reset 理解为敌人也能被真人操作。第一次初始加载不通过完整轮转，不自动发一次相同的初始收入/恢复；战役资金由关卡初始化写入。

依据：`MainDisplayable.sub_cff:6365`、gameState 8 分支 `4058`。没有证据显示结束回合强制所有单位已行动完才允许。

## 胜负

自由对战：某未关闭阵营仍有存活的主指挥官 **或** 至少一座己方城堡，就在胜负扫描中代表其队伍；当这些阵营仅剩一个队伍时该队获胜。剩余普通部队不是这段胜负扫描的保活条件；它不同于“没有部队且没有城堡则跳过该玩家”的条件。多个指挥官时胜负扫描使用 `fractionKings` 主指挥官，未遍历所有指挥官。依据：`MainDisplayable.updateScript:8191`。

战役通用失败：所有蓝方已登记指挥官 state 3 **且** 蓝方城堡数 0。语言目标的“Galamar must survive”并不总是由“Galamar 死亡立即失败”实现；每关附加失败/完成条件见 [战役](CAMPAIGN.md)。第五关和第七关水晶有独立保护判断；最终关击败 Saeth 可推进结尾，不要求清掉全部杂兵和城堡。

## 逻辑时间与动画

Renderer 一次循环执行一次 `currentDisplayable.update` 和 repaint，目标间隔 `1000/FPS`；Manifest 为 15，即理想约 66 ms。与此同时 `MainDisplayable.update` 每次把逻辑计数加 50，`Sprite.update` 同样加 50；`.sprite FrameDelay n` 存成 `n*50`。所以这里的“250”意味着 5 次更新，在理想 15 FPS 下约 330 ms，不是精确 250 ms 的现实时间。

脚本 Wait n 是更新次数倒计时；其推进还受当前显示层、对话、地图镜头等暂停条件影响。精灵默认每次最多推进一帧并重置计数，循环次数与 active、bounceMode、autoDeactivate 控制生命周期。单位慢速 6 / 快速 12 像素每次更新；剧情会另设 2、4。

UI 菜单也占有 update，因此世界逻辑不是稳定现实时间定时器。重制前需决定以原版步数/实测节奏为准，不能直接把旧代码“ms”换成现代计时器。依据：`Renderer.run:674`、`MainDisplayable.update:3857`、`Sprite.update:607`、`Sprite.readSpriteData:164`。

侧面战斗人数算法：`segment=100/CharCount; n=HP/segment`，HP 非 100 且有余数时 n+1。满血 3 人配置仍绘制 3；受伤阈值受整数 33 影响，不能简单改成浮点 `ceil(HP/100*3)`。水晶 CharCount=0，进入此函数会除零，原流程用没有战斗角色的路径规避。每个兵种动画状态机还涉及弹道、阵列、爆炸与抖动，见 `CombatAnimation.java`；本次提取了完整帧定义，没有声称已经验证全部动作逐帧时间线。
