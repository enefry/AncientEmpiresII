## 行动顺序与调度

`sub_1022`：取当前方 state 0 单位，按类型优先值升序排列；同优先值按 HP 升序，完全相等稳定保留输入顺序。

| 单位 | 优先值 |
| --- | --- |
| 士兵 | 0 |
| 幽灵 | 1 |
| 弓箭手 | 2 |
| 其它 | 3 |

因此先让士兵占地、幽灵加光环，再处理其它部队；优先值相同的受伤部队先行动。该解释来自顺序与规则配合，排序本身是源码可直接确认的事实。

`sub_1043` 分阶段显示范围、移动、攻击/召唤/占领/修复并结束行动。若最佳目的格被同方 state 0 单位占据，将阻挡者放入 `var_381f` 先重新安排，再处理原行动；不是允许两个单位永久叠放。AI 使用快速移动 12。

## 战略目标

`sub_109f` 的目标数组每行五项：`x,y,威胁权重,距离,已分配支援/自身强度`。候选包括己方士兵、指挥官和建筑。

敌人/自身强度估算：

```text
Q(unit,x,y,target) = (攻击下界 + 攻击上界 + 基础防御
                    + 对该目标的攻击加成 + 在该格的防御加成)
                    * 当前HP / 100
```

来自 `Unit.sub_462:345`，**不是期望伤害**；不抽随机值，也没有模拟实际先攻和反击扣血。目标为空时也包含地形/状态，anti_air 等特定目标奖励才受 target 影响。

己方士兵/指挥官会累加曼哈顿距离 1…5 内敌人的 Q；某些进攻情形转向敌指挥官，条件包括自身没有主指挥官，或 `currentTurn>=15`、目标方活单位 <4、自方 >=8。己方/已预约建筑周围的威胁视可占领属性分类计算。已有支援记账可降低重复派兵意愿，按 player transition 清理。

决策顺序：

1. HP<50 且找到合适建筑时，优先去恢复；可选择同队建筑，也可选择可占领且可达的非同队建筑。
2. 自方有主指挥官、单位可占领且有未预约的合适建筑时，优先最近的占领目标。
3. 否则计算 `威胁权重 * 最近有效目标距离 / 该目标距离 − 已分配强度`，挑最高目标；距离最小按 1 处理。

选中的目标登记支援量、目标建筑预约者，并从目标反向传播预算 10 的范围到 `var_39e3`，给局部移动评分提供趋近信息。反向传播仍使用该兵种的地形费用，不能简化成圆形欧氏距离。

## 候选行动评分

扫描地图 x 外层、y 内层，只评估 alpha>0 的格。普通兵种尝试从该格攻击所有射程内目标；召唤兵种再尝试各墓碑；最后评估“仅移动/停留”。投石车只在保持原位时枚举攻击。

下面是 `sub_10cb:7469` 各项得分的语义展开。所有项累加，判断条件照源码，不是互斥的统一策略。

| 条件 | 分数 |
| --- | --- |
| 有建筑战略目标且有主指挥官，候选在反向预算范围内 | `100 + 100*remaining/10` |
| 上述情况不在反向范围内 | `100*(原距离−新距离)/(moveBudget−1)`；低费用地形额外 +20 |
| 上述情况未选攻击且能占非同队城堡 | +300 |
| 上述情况未选攻击且能占/修城镇或废墟 | +200 |
| 元素生物在水域 | +25 |
| 女术士选择墓碑召唤 | +100 |
| 幽灵且传入墓碑参数不为空 | `25 * 距离1…2同队单位数`；原调用流程通常不给幽灵墓碑候选，不能擅自当通用光环奖励 |
| 攻击不会反击的活目标 | `2*Q(己方,候选格,目标)` |
| 攻击可反击的活目标 | `3*Q(己方,候选格,目标)/2 − Q(目标,候选格,己方)` |
| 活目标是指挥官 / 水晶 | 分别 +25 / +100 |
| 城镇伪目标有阵营且未预约 | `Q(己方,候选格,伪目标)/2` |
| 地形防御 | 直接加配置防御值 |
| HP<100 且候选是同队建筑 | `100−HP` |
| 候选在反向范围内 | `50 + 100*min(remaining,k)/k`，`k=10−moveBudget/2` |
| 否则有战略目标 | `50*(原距离−新距离)/(moveBudget−1)` |
| 阻挡其它尚未行动、已预约且能赶到的建筑占领者 | −200 |
| 移动距离奖励 | `20*曼哈顿移动距离/(moveBudget−1)` |

反击估算 `Q(目标,候选格,己方)` 的坐标参数是己方候选格，并没有传目标真正所在格；这属于原式，不能静默纠正。算法也未显式估算反击后血量、击杀概率、多回合收益或沿途危险。实际文档中的 Q 参数位置必须与源码一致。

只有严格 `score>best` 才替换当前最佳。完全平分优先保留 x/y 扫描最先出现的格、其目标列表最先出现的目标；同一格先攻击、再召唤、最后空行动。原版 AI 的重复可预测行为部分来自这些平手规则。

## 招募

当前已有部队全部安排后才招聘。若有己方城堡，选择最靠近敌方可占城堡单位的城堡；未找到这种敌单位时参照其它方城堡距离，保留首个城堡作初值。城堡候选是己方所有权而非同队共享。

先尝试复活登记的死亡指挥官；循环未在首个成功时立即 break，可能复活多位，只把最后一位作为马上规划的 var1，需实测确认这种多指挥官边界。若无复活成功，按优先级：

1. 士兵不足 2 支且能买，则买士兵。
2. 否则弓箭手不足 2 支且能买，则买弓箭手。
3. 否则若金币 >=1000，或自方单位 <8，或己队单位少于敌队，生成可买类型 1…11 列表：该类型不足 1 支或价格 >=600；在列表中随机选一个。

所有选择仍需通过 `canBuyUnit`：上限排除骷髅、解锁上限、价格为正、足够金币，以及从城堡存在可达空格。`allowedUnits` 默认最大 8，指挥官 type 9 以已有对象复活，不能随意招新；骷髅/水晶 cost −1 不进入常规候选。新买单位立即进行规划，随后继续招聘直到不能再买或不满足策略。

## 最后一关

战役 `m7` 的红方主指挥官 Saeth 每次 CPU 回合得到特别处理：从蓝方活单位列表随机取一个目标，执行 Heaven's Fury，不按照通常候选评分移动攻击。伤害一般是 `25 + randomToRange(25)`，即 25…49，并限制到目标剩余 HP；没有普通伤害公式中的防御/HP缩放，没有反击。这一特殊调用在 `MainDisplayable:6903`，伤害在 `4232`。

开场剧情也演示一次天怒，但当时 `var_29c1=false`，跳过普通扣血，由剧情另行删除演示目标。不能把开场演示与后续 CPU 技能共用一次伤害事件后再删单位，否则会重复改变数值。
