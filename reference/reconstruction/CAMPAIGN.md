# 八关战役还原

关卡地图是静态布局，剧情与增援大部分在代码里。选定 JAR 没有有效 `mN.script`，因此以硬编码状态机为行为基准；源码目录第一关有 `m0.script`，不能直接当作选定包的运行路径。

主依据：`reference/inputs/AEIIRM_src/src/aeii/MainDisplayable.java` 的 `initStoryMission:7646`、`updateScript:8169`，文本 113–138、215–287。逐 case 的原语句、坐标、对话 ID 见 [213 个状态证据](CAMPAIGN_STATES.md)；初始化中的出生/移动另在上述方法，不全在 case 摘录中。编号从 m0 起，中文第 n 关=n−1。

## 初始参数

`allowedUnits` 是可买兵种最大 ID，不是可以创建的总种类数，也不禁止剧情刷更高级单位。主指挥官复活可另走 type 9 例外。

| 地图 | 任务名 | 地图尺寸 | 蓝 / 红金币 | allowedUnits | 蓝方主指挥官 | 状态 case |
| --- | --- | --- | --- | --- | --- | --- |
| m0 | TEMPLE RAIDERS | 12×12 | 0 / 0 | 0 | Galamar | 0–36 |
| m1 | TO THE RESCUE | 15×12 | 300 / 50 | 1 | Valadorn | 1–27 |
| m2 | PATH OF SHADOWS | 10×17 | 0 / 0 | 0 | Galamar | 0–22 |
| m3 | REINFORCEMENTS | 16×16 | 400 / 400 | 7 | Galamar | 0–19 |
| m4 | ESCORT DUTY | 20×12 | 0 / 0 | 0 | Galamar | 0–26 |
| m5 | NORTHBOUND | 12×20 | 600 / 600 | 7 | Valadorn | 0–6 |
| m6 | RENDEZVOUS | 16×18 | 400 / 600 | 8 | Galamar；后援 Valadorn | 0–34 |
| m7 | HEAVEN'S FURY | 14×18 | 800 / 200 | 8 | Galamar + Valadorn | 0–36 |

这些资金是 initStoryMission 写入值。地图原始单位数和正式开始可控时的部队数不同，例如 m6 `.aem` 仅 1 条单位，开场另外创建士兵、弓箭手、女术士与水晶。

通用失败扫描：蓝方全部登记指挥官已死亡且没有蓝方城堡；不是任何一名指挥官死亡即失败。以下附加条件按源码标注，不能只照任务说明文本写规则。

## 第一关 m0：勇气神庙

剧情：三名蓝方入场部队向内移动，镜头展示 `(9,3)` 神庙守军被杀；普通游戏开始后穿插选择、移动、攻击、回合和地形等教程。

状态 22：第一批红方活单位全部消灭，暂时停用操作。状态 24 在 `(1,1)` 生成红弓箭手，向 `(1,2)` 入场；状态 26 在 `(10,10)` 生成红士兵，向 `(10,9)` 入场，若目的地被占可用剧情空位调整。随后恢复操作，不能第一批清空就直接胜利。

状态 30：红方活单位再次为 0 且 `gameState==0`，触发结束对话；状态 36 `completeMission`。本文所称活单位使用 `countUnits(-1,-1,side)`：排除墓碑，但并非“只有普通兵”。文本 221–230，教程状态 14–21。

脚本差异：JAR 仅 `m0.script.bak`；提供源码有效脚本的 Case 28 多一条 `NextState`，与硬编码推进对应。直接把 `.bak` 改名为 `.script` 会改变加载路径，不能作为无差别还原。

## 第二关 m1：智慧神庙

开场蓝部队从南边进入，主角变为 Valadorn。红士兵与水晶形成跟随链离场，守军被击倒。教程引入招募、占领与指挥官复活。

状态 20 要看到蓝方占领事件（gameState 9），然后继续教程；状态 22 等蓝或红主指挥官有一方进入死亡状态，才显示指挥官复活说明并到后续胜利扫描。该教程前置条件不能在现代流程中无意识漏掉。

状态 23：红方活单位=0 **且** 红方城堡=0，推进结束对话，状态 27 完成。地图外蓝部队是输入中 `(7,12)`、`(9,12)`，地图高仅 12：初始化代码明确将它们移入场内，不是地图解析损坏。文本 231–240。

## 第三关 m2：迷雾森林

开场将南侧 Galamar 和部队移入场。状态 7/8：扫描蓝方已经结束行动（state 2）的单位，任一 `x<=4 或 y<=10`，触发伏击；墓碑出现还会显示召唤教程。

伏击先从西、东、北刷 5 只凶狼和 1 个幽灵：两狼由 `(-1,8)、(-2,7)` 移入；一狼由 `(12,6)` 移入；北侧两狼与幽灵由负 y 移入。状态 14 另在 `(3,8)、(4,7)、(5,8)` 生成红元素生物，展示对话后状态 19 删除这三者、在同格换成蓝元素生物，成为援军。

状态 21：红方活单位=0，状态 22 完成；没有额外占城堡条件。文本 241–248。地图二进制中的蓝方 `(8,17..19)` 在外部，初始化脚本将其进入棋盘；需要允许临时离场单位对象存在。

## 第四关 m3：生命神庙

初始化额外创建蓝士兵、元素生物、女术士从负 x 入场。镜头转场后把 Galamar 放到 `(7,1)`，三援军分别 `(5,4)、(7,5)、(3,3)`。红投石车演示攻击，将城镇 `(4,9)` 改为废墟。

教程引入修复与投石车。状态 16：红方活单位=0 且红方城堡=0，状态 19 完成。任务文本要求保护神庙，但这一分支没有找到“神庙被打坏立即失败”的独立检测；神庙 Type 7 本身也不是投石车城镇伪目标 Type 8。文本 249–255。

## 第五关 m4：护送水晶

蓝队在北侧入场，引用蓝方水晶 `var_3c5c`。全阶段检查它的死亡状态并触发失败。

游戏中按已结束行动的蓝单位位置依次触发四组伏击：

| 当前状态 | 区域触发 | 出生区域 / 增援 |
| --- | --- | --- |
| 4 | 任一蓝单位 state 2，x<=8 | `(4,4)`：2 骷髅、1 弓箭手，分散至 `(4,1)、(5,2)、(4,3)` |
| 11 | 任一蓝单位 state 2，y>=7 | `(6,10)`：弓箭手、2 凶狼，移到 `(5,10)、(7,8)、(7,9)` |
| 15 | 任一蓝单位 state 2，x>=8 且 y>=6 | `(12,5)`：2 凶狼、1 魔像，移到 `(12,7)、(12,5)、(12,6)` |
| 19 | 任一蓝单位 state 2，x>=15 且 y>=8 | `(18,8)`：2 凶狼、魔像、弓箭手，移到 `(16,10)、(18,10)、(17,10)、(18,9)` |

完成条件有两条：状态 25 中水晶 state 2 且 `x>=15 && y>=11` 可以直接进入完成阶段；或者状态 25 红方活单位=0 也能进入完成阶段。水晶到达条件不是只有一个精确格，也未要求清空敌军。文本 256–259；实际过关条件由 `updateScript` m4 分支上方和 case 25 共同决定。

## 第六关 m5：北上

Valadorn 主队进攻 Thorin 城门，起始双方 600 金币、可买到投石车。剧情较短，没有上述分组坐标伏击。

状态 3：红方活单位=0 且红方城堡=0；对话后状态 6 完成。文本 260–261。

## 第七关 m6：城外会合

开场由 Galamar 的跟随链创建蓝士兵、弓箭手、女术士、水晶，随后解除跟随关系开始游戏。只有 scriptState<=10 时有水晶保护失败检查。

状态 4：`currentTurn>=2`，在 `(11,8)` 刷红凶狼、士兵、女术士、弓箭手并散开。状态 10：任一蓝已结束行动单位 `x<=9 或 y>=10`，**或** 红方活单位全灭，触发水晶被抢事件。

红龙从地图右外侧飞入水晶格，水晶随后跟着龙从左侧离场，二者被删除。红军从西侧入场：Demon Lord、2 士兵、2 巨龙、幽灵、2 魔像；中南部再刷士兵、魔像、元素生物、女术士。随后 Valadorn 和蓝魔像、龙、幽灵、弓箭手从南侧增援。

状态 32 改任务文本为 ID 138（沿西边道路击败指挥官、占领城堡）；状态 33 要红方活单位=0 且红方城堡=0，状态 34 完成。存档恢复若此关 scriptState>32，会重建更新后的目标文本。水晶被剧情拿走不能误判为“玩家护送失败”。文本 262–270、138。

## 第八关 m7：古代城堡与天怒

开场调整指挥官身份：红主指挥官为 Saeth（variant 3），蓝 Galamar（0）、Valadorn（2）。三颗水晶逐一移动到 `(7,2)` 后删除；Saeth 前往同格。随后演示天怒攻击蓝方 `(9,15)` 单位：技能普通扣血关闭，由剧情删掉演示受害者，再开启正常技能伤害。

正式游戏状态 20：当 Saeth 被击倒，死亡处理将 `var_29de=true`，直接进入结尾；不要求所有红部队或红城堡清空。CPU 对 Saeth 用专门随机天怒，不使用通常评分。伤害和开场差异见 [AI](AI.md)。

结尾淡出后清场并重建演出部队：Saeth `(7,2)`、两蓝指挥官 `(6,3)、(8,3)`、两士兵 `(6,1)、(8,1)`。播放文本 281–287、消失、长抖动、结局画面及工作人员名单 288，最后转到 gameState 14。它不简单调用前 7 关的 `completeMission`。

## 状态推进要点

- `moveMapAndCursor` 本身会 `scriptState++`；许多 case 没有显式 ++，但不是永远停住。
- 脚本等待是计数步数，不是直接等待现实 n 秒；`mapTarget` 尚未抵达时脚本返回，对话显示层也影响更新。
- `lastFinishedMoveUnit` 在脚本末尾清空，教程触发依赖一次性结束行动事件。
- 对话 portrait ID 与 commander variant、阵营 ID 是不同体系；源码使用 0…5 及 −1，不要把全部对话头像按单位阵营染色。
- 完整 case 摘录不等于现代事件脚本；转换之前必须实测镜头、等待、启停操作和出生/删除顺序。
